## How I build

| | Principle | In practice |
| :---: | :--- | :--- |
| **01** | **Design before code** | Architecture, user flows, database schema and interface designs are finalised before any code is written. |
| **02** | **Sequential development** | One system at a time. No forward dependencies. Phase 0 → Phase 1 → Phase 2 → Phase 3, in order. |
| **03** | **Controlled failure** | Systems fail. The goal is failures that are predictable, traceable and debuggable — not perfect systems no one understands. |
| **04** | **Stack by problem type** | The framework is assigned by problem type and locked in an architecture decision record. Not debated per project. |
| **05** | **Observability from day one** | Sentry, Better Stack and Prometheus are wired in at Phase 0, not added later when something breaks. |
